# Роадмап gost-report-skill

## Phase 1: Качество выходного docx (стили и баги)

Цель: довести качество генерируемого .docx до уровня, когда ручная доводка минимальна или не нужна.

### Стратегия выбора инструмента

Три инструмента для фиксов, в порядке предпочтения:

1. **reference.docx (стили)** — самый чистый путь. Если можно решить настройкой стиля в шаблоне — решаем здесь
2. **Lua-фильтры** — пре-обработка на уровне Pandoc AST до генерации docx
3. **build.py (python-docx)** — пост-обработка готового docx. Самый гибкий, но самый «грязный»

Сначала пробуем стили, потом Lua, потом python-docx. Комбинируем при необходимости.

### Задачи

#### H1 по центру

Заголовки первого уровня (`#`) — основные разделы (Ход работы, Выводы, Краткие теоретические сведения, Задание) — должны центрироваться. Заголовки второго уровня (`##`) — подразделы — по левому краю.

Предположение: настройка стиля `Heading 1` в reference.docx = центрирование. Нужно проверить эмпирически.

После фикса — обновить SKILL.md: конкретизировать для агента различие `#` и `##`, дать явный перечень что является `#`, а что `##`.

#### 12pt подписи после изображений

Основной текст — 14pt TNR. Подписи к рисункам должны быть 12pt и по центру.

Исследовательский вопрос: в какой стиль docx Pandoc маппит caption из `![Рисунок 1 — ...]()`? Если это отдельный стиль (Image Caption, Caption, Figure) — настраиваем в reference.docx. Если обычный Body Text — нужен Lua-фильтр или пост-обработка.

#### Autofit таблиц по контенту

Сейчас таблицы с фиксированной шириной колонок, что приводит к неоптимальному распределению ширины.

Варианты:
- Настроить стиль таблицы в reference.docx с autofit
- Пост-обработка в build.py через python-docx (table.autofit)

Нужно проверить оба варианта эмпирически.

#### Серые таблицы

Предположительно пофикшено в текущем reference.docx (убрано из списка ограничений). Подтвердить при тестировании.

### Исследование: экосистема Lua-фильтров Pandoc

Нужно разобраться:
- Что можно делать на уровне AST (переназначать стили, менять атрибуты элементов)?
- Есть ли готовые фильтры для типичных задач (caption styling, table formatting)?
- Границы: что фильтр может, а что только пост-обработка?

Результат исследования влияет на выбор инструмента для каждого бага из Phase 1.

## Phase 2: Setup Wizard

Цель: файл-инструкция SETUP.md, который агент читает при первом запуске. Позволяет пользователю настроить окружение и титульный лист с минимальными усилиями.

### Блок A: Установка окружения

Платформо-специфичные инструкции: Ubuntu, macOS, WSL.

Принцип «прорубленной дорожки»: каждая инструкция проверена практической установкой на целевой системе (желательно в нескольких конфигурациях). Не из документации — из реального опыта.

Основные грабли:
- Шрифт TNR: на Linux/WSL — `ttf-mscorefonts-installer`, на macOS — зависит от конфигурации
- Pandoc: в некоторых дистрибутивах версия ниже 3.1.12, нужно ставить вручную

Расширение на другие платформы — по требованию. Docker — overkill для этого проекта.

### Блок B: Настройка титульного листа

Логика:
1. «Из какого вы вуза?»
2. Если вуз есть в готовых заготовках (`templates/universities/`) — подключить готовый reference.docx
3. Если нет — провести через адаптацию

Адаптация титульного листа — ключевой исследовательский вопрос: может ли агент через python-docx заменить содержимое титульного листа с сохранением стилей? reference.docx = стили (глобальные) + титульный лист (содержимое). Стили не привязаны к конкретному листу. Значит адаптация — по сути замена содержимого при сохранении стилей.

Стратегия: по максимуму делегировать на агента, запрашивать помощь пользователя только где необходимо. Если агент может скачать шаблон с сайта вуза и адаптировать автоматически — идеально.

## Phase 3: Титульные листы вузов

Цель: готовые заготовки reference.docx для популярных вузов РФ.

### Скоуп

- Топ-5 крупнейших вузов России
- Топ 5-7 крупнейших вузов Санкт-Петербурга (приоритет — питерские вузы)

### Источник

Официальные сайты вузов, открытый доступ. Если у вуза нет публичного шаблона титульного листа — пропускаем.

### Принципы

- Берём самый типовой титульник, не покрываем вариативность по факультетам/кафедрам
- Для кастомизации под конкретный факультет — Setup Wizard

### Хранение

```
templates/universities/<вуз>/reference.docx
```

### Проверка

Каждый шаблон протестировать: полная сборка отчёта с заполнением YAML-метаданных.
